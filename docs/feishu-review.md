## 启动后续审批（T03 已完成）

T03 已有发送台账，不应再次执行；后续演示应让同事发送新的测试邮件，生成新的 003 草稿，再替换 source 和 draft，不清除 ledger 或重发 T03。

在 Codex 本项目中说：

> 检查唯一审批服务和邮件执行环境，将刚才展示的这封新 003 草稿交给飞书审批，有效期 20 分钟。只在我点击批准后发送对应版本，修改后重新审核，拒绝或超时不发送。

程序入口（从项目根目录运行）：

```bash
rtk proxy python3 skills/agentmail-assistant/scripts/feishu_review.py run --source state/session.json --draft 新草稿ID --reviewer ou_9883864148e1680efa5720a7fb91da69 --minutes 20
```

程序先等待监听 ready，再发送卡片；输出 `card_sent: true` 才代表飞书已接受卡片消息。若提示权限或回调未订阅，先解决该错误，不要宣称审批可用。仅看 JSON 而不联网可将 `run` 改为 `preview`，输出 `state/feishu/preview-card.json`。

飞书中打开机器人的私聊：

1. **批准发送**：按卡片展示的收件人与完整正文回复一次；不新增抄送或附件。
2. **修改正文**：进入编辑表单，填写完整新正文，点击“保存并重新审核”；新版本出现后再点击“批准发送”。保存本身不发邮件。
3. **拒绝**：结束这张审批单，不发邮件。

界面最终“已提交邮件服务”表示 queued，不等于收件人已收到。让同事在邮箱核对 T03。若按钮无响应，查监听进程和回调配置；不要转而重复发送邮件。

当前共33项离线测试通过；完整状态与未完成项见[测试状态](test-status.md)。

- 当前卡片入口只处理 003。004 仍先在 Codex 作业务决定；005 没有批准发送入口。001/002 沿用原规则。
- 独立限时模式每次只审核一封，运行最多 20 分钟；Mac mini 常驻队列可连续接收审批单，各卡片期限独立。两者都不监听业务新邮件，也不调用 LLM 自动分类。无需为按钮回调额外运行 LLM。
- 保持本机联网、唤醒和处理进程运行。截止时间后不再接受批准，程序会将卡片更新为“审批已结束”并移除按钮，然后退出监听。如果本机断网或进程被强制终止，界面更新可能失败；下一轮启动时会补更新同封邮件的旧卡片。飞书提示“目标回调服务不在线”时，应先检查截止时间及 event status，不能反复点击过期卡片。
- 持久记录在 `state/feishu/<审批单ID>.json`，包括审核人、邮件与飞书消息 ID、版本、正文哈希、去重事件和发送结果；不保存回调令牌。原邮件去重仍使用同一个 `state/ledger.json`。
- 旧按钮、其他人点击、重复事件、过期、正文或规则变化都不能触发新发送。进程中断或发送结果不明确时不自动重试，也不要删除台账。
- 独立限时模式停止当前处理进程用 Ctrl+C，卡片结束后程序退出。Mac mini 常驻服务不随单张卡片结束而退出，停止方法见运维文档。
- 在原期限内修复并重启未批准的卡片，可使用 `rtk proxy python3 skills/agentmail-assistant/scripts/feishu_review.py resume --ticket 审批单ID`，不重发卡片、不延长原期限；只接受恢复后新点击，旧点击不补作批准。已过期或有批准/发送记录的卡片不能恢复。
- Mac mini 已部署审批队列和进程托管；全天方案仍需邮件调度、模型判级、运行告警及更完整的恢复验证。
